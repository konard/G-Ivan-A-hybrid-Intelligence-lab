## Методология

Задача поставила жёсткий контракт: **стоимость берётся только там, где она явно
напечатана**. Методология построена так, чтобы этот контракт был машинно
проверяемым, а не декларативным.

**1. Источник данных.** GitHub REST API через `gh` CLI: список закрытых PR
(`gh pr list --state closed`) и все комментарии репозитория одним постраничным
запросом (`gh api repos/OWNER/REPO/issues/comments --paginate`). Тело PR
разбирается тем же парсером, что и комментарии.

**2. Извлечение стоимости.** Распознаются три (и только три) явных числовых
маркера, которые печатает инструментальная обвязка в блоке
`## 🤖 Solution Draft Log`:

| Приоритет | Маркер | Семантика | Сессий |
| --- | --- | --- | --- |
| 1 | `### 💰 Cost: **$X**` | итоговая цифра, напечатанная Claude Code | 214 |
| 2 | `- Calculated by Anthropic: $X USD` | цифра, посчитанная провайдером (ранний формат лога) | 71 |
| 3 | `- Public pricing estimate: $X USD` | оценка по публичному прайс-листу; единственная форма для логов Codex | 248 |

Приоритет применяется сверху вниз внутри одного лога: если есть цифра
провайдера, публичная оценка из того же лога не используется — двойного счёта
нет. Комментарий без любого из трёх маркеров стоимости не даёт.

**3. Запрет на достройку.** Ни одна цифра не вычисляется по токенам, не
экстраполируется со «похожих» PR и не переносится с соседних сессий. PR без
маркера получает статус «стоимость не указана» и попадает в приложение A.
В агрегатах такой PR участвует только счётчиком задач.

**4. Определение модели.** Семейство определяется по строкам блока
`### 🤖 **Models used:**` — `- Tool:` (`OpenAI Codex` / `Anthropic Claude Code`)
и `**Model: ...**`. Ранний формат лога не печатал точное имя модели, но печатал
запрошенный алиас `- Requested: \`opus\`` — он и используется как имя модели
(значение `Claude Opus` без версии в [таблице 3](#3-разбивка-по-конкретным-моделям)).
Если блока нет вовсе, инструмент выводится из формы маркера: цифру
`Calculated by Anthropic` печатает только Claude Code.

**5. Воспроизводимость.** Весь разбор выполняет скрипт
[`collect-pr-costs.py`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/hub/exp/ai-execution-statistics-543/collect-pr-costs.py);
машиночитаемый результат с построчными фактами по каждому из 432 PR —
[`pr-cost-dataset.json`](https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/research/hub/exp/ai-execution-statistics-543/pr-cost-dataset.json).
Числа отчёта сняты запуском, лог которого сохранён в контейнере. Репозитории
живые: при расхождении доверять следует полю `summary.data_horizon` датасета,
а не тексту отчёта.

## Приложение B. Ограничения полноты данных

Ограничения перечислены явно, чтобы цифры не читались шире, чем позволяет
источник.

1. **Единица «сессия», а не «задача».** 87 PR содержат более одной сессии
   (доработки после ревью, перезапуски). Стоимость PR — сумма его сессий.
2. **Разная природа цифр.** 248 из 533 сессий (все логи Codex и часть ранних
   логов Claude) дают **оценку по публичному прайсу**, а не счёт провайдера;
   285 сессий дают цифру, напечатанную инструментом или посчитанную Anthropic.
   Смешивать их в одну сумму — вынужденное решение: другой цифры в источнике
   нет. Там, где в одном логе есть обе (71 сессия), взята цифра провайдера.
   Замеренная в этих 71 логах разница между публичной оценкой и цифрой
   провайдера доходила до −20 % на отдельных сессиях.
3. **Ранний период не имеет пробелов, но имеет иную детализацию.** Логи до
   июля 2026 не печатали точное имя модели (30 сессий `Claude Opus` без
   версии); семейство модели при этом известно.
4. **Стоимость ручной работы человека не учитывается** — источник её не
   содержит.
5. **Срез живой.** На момент среза открыт 1 PR в каждом репозитории; по
   контракту задачи открытые PR не анализируются. Повторный запуск скрипта на
   более поздней дате даст другие числа.
6. **Комментарии, удалённые из PR, недоступны через API** — если лог сессии был
   удалён, PR попадёт в приложение A. Отличить «сессии не было» от «лог удалён»
   по данным GitHub нельзя.
