# Индустриальные практики онбординга ИИ-агентов: корневые инструкционные файлы

## Цель и вопрос исследования

Какие механизмы индустрия использует, чтобы правила репозитория гарантированно попадали в контекст
ИИ-агента, и что из этого применимо к экосистеме Хаба (issue
https://github.com/G-Ivan-A/hybrid-Intelligence-lab/issues/547).

## Обзор практик

### AGENTS.md — открытый формат

- Источник: https://agents.md/ и https://github.com/openai/agents.md
- Простой Markdown в корне репозитория; поддерживается Codex и рядом других агентов.
- Разрешены вложенные `AGENTS.md` в подкаталогах; действует правило «ближайший файл побеждает».
- Явно позиционируется как «README для агентов»: то, что мешало бы человеку в README, но нужно агенту
  (команды сборки, соглашения, границы).
- Формат передан в открытое управление (Agentic AI Foundation) и используется десятками тысяч
  публичных репозиториев, то есть является де-факто стандартом, а не экспериментом.

### Codex — цепочка инструкций

- Источник: https://developers.openai.com/codex/
- Инструкции собираются по цепочке: глобальный `~/.codex/AGENTS.md` → `AGENTS.md` в корне проекта →
  `AGENTS.md` в рабочем каталоге. Файлы **конкатенируются**, более специфичный переопределяет общий.
- Следствие для нас: корневой файл обязан быть самодостаточным и коротким, потому что он всегда
  попадает в контекст целиком.

### Claude Code — `CLAUDE.md`

- Источник: https://code.claude.com/docs/en/memory
- Claude Code читает `CLAUDE.md` (проектный, пользовательский, локальный), а не `AGENTS.md`.
  Совместимость достигается импортом `@AGENTS.md` внутри `CLAUDE.md` или симлинком.
- Документация рекомендует держать файл коротким и конкретным; распространённый ориентир — до ~200 строк.
- Ключевая формулировка практики: memory-файл — это **контекст, а не принудительная конфигурация**.
  Для гарантий используются hooks (https://code.claude.com/docs/en/hooks) — детерминированные
  обработчики, срабатывающие на события инструментов.

### GitHub Copilot

- Источник: https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-custom-instructions
- Репозиторный файл `.github/copilot-instructions.md` + гранулярные
  `.github/instructions/*.instructions.md` с фронтматтером `applyTo` (glob-таргетирование).
- Рекомендация документации: держать инструкции короткими и самодостаточными, порядка двух страниц;
  избегать ссылок на внешние ресурсы как на источник обязательных правил.

### Cursor

- Источник: https://cursor.com/docs/context/rules
- Правила живут в `.cursor/rules/*.mdc` с метаданными `alwaysApply`, `globs`, `description`;
  поддерживаются вложенные каталоги правил. Legacy `.cursorrules` объявлен устаревшим.
- Рекомендация: правило меньше 500 строк, декомпозиция на несколько правил вместо одного большого.
- Cursor также распознаёт `AGENTS.md`, тогда как произвольные `.md` в репозитории игнорируются.

### Ограничение внимания в длинном контексте

- Liu et al., «Lost in the Middle: How Language Models Use Long Contexts», TACL 2023 —
  https://arxiv.org/abs/2307.03172
- Показано U-образное распределение качества: информация в начале и в конце контекста используется
  существенно лучше, чем в середине; деградация усиливается с ростом длины контекста.
- Прямое следствие для дизайна: обязательные запреты нельзя закапывать в середину длинного файла,
  а длинные правила нельзя грузить целиком «на всякий случай».

## Сводная матрица

| Инструмент | Читаемый файл | Автозагрузка | Ориентир по объёму | Механизм гарантии |
|---|---|---|---|---|
| Codex | `AGENTS.md` (цепочка global → root → cwd) | да | коротко, файл грузится целиком | нет, только контекст |
| Claude Code | `CLAUDE.md` (+ импорт `@AGENTS.md`) | да | ~200 строк | hooks |
| GitHub Copilot | `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md` | да | ~2 страницы | нет, только контекст |
| Cursor | `.cursor/rules/*.mdc`, `AGENTS.md` | да (по `alwaysApply`/`globs`) | <500 строк на правило | нет, только контекст |
| Хаб (сейчас) | `ai-rules/`, `standards/` | **нет** | десятки тысяч строк | валидаторы в CI |

## Выводы, применимые к экосистеме

1. **В1. Корневой файл фиксированного имени — обязательное условие доставки.** Ни один инструмент
   не найдёт `ai-rules/` самостоятельно. Единственный формат, покрывающий максимум агентов одним
   файлом, — `AGENTS.md` в корне.
2. **В2. Корневой файл должен быть диспетчером, а не сводом.** Он всегда грузится целиком (Codex),
   а внимание к середине длинного контекста падает (Liu et al.). Значит: жёсткие короткие правила,
   явные запреты в начале, маршрутизация ссылками — вместо копирования правил.
3. **В3. Ссылки должны быть абсолютными URL.** Агент часто работает над спицей, а канонические
   правила лежат в Хабе; относительный путь в спице не разрешается. Это же требование зафиксировано
   как НФТ issue #547.
4. **В4. Единый файл для всех моделей достижим.** Модель-специфичные различия (Codex, Claude Opus,
   Qwen, DeepSeek, YandexGPT, GigaChat) касаются способа загрузки, а не содержания правил. Поэтому
   правильное решение — один `AGENTS.md` с отдельной секцией «как этот файл подхватывает каждый
   инструмент» и тонкими указателями (`CLAUDE.md` с импортом, `.github/copilot-instructions.md`
   со ссылкой), а не отдельные CODEX.md/OPUS.md с дублированием содержания.
5. **В5. Контекст не является принуждением.** Индустрия закрывает это hooks (Claude Code) и CI.
   Для Хаба эквивалент — расширение `tools/validate-repository-structure.sh` явными запретами и
   pre-commit/CI-валидация структуры issue. Без этого `AGENTS.md` остаётся рекомендацией.
6. **В6. Распространение важнее написания.** Copilot и Cursor работают только с файлами внутри
   конкретного репозитория. Значит `AGENTS.md` должен принудительно инжектироваться в каждую спицу
   (`tools/inject-agents-md.sh`), иначе Aether-Orbis снова останется без генома.

## Дизайн `AGENTS.md` для экосистемы (обоснование структуры)

Черновик: https://github.com/G-Ivan-A/hybrid-Intelligence-lab/blob/main/templates/agents-md-root-draft.md

- Секционирование XML-тегами (`<hard_rules>`, `<forbidden>`, `<routing>`, ...) — жёсткие границы
  блоков для парсинга LLM, требование НФТ №2 issue #547.
- Запреты размещены до маршрутизации: начало контекста — зона максимального внимания (В2).
- Маршрутизация оформлена таблицей «тема → абсолютный URL»: минимальный объём при полном покрытии (В3).
- Блок про модели описывает загрузку, а не отдельные правила (В4).
- Объём удерживается в пределах индустриальных ориентиров (~2 страницы / <200 строк содержания).

## Ограничения исследования

Изучены публичные документации инструментов и открытый формат AGENTS.md; количественное
исследование выборки репозиториев не проводилось. Приведённые ориентиры по объёму — рекомендации
вендоров, а не измеренные пороги.
